# payload/ (CMS, package `payload-app`)

Loaded when Claude works in `payload/`. Repo-wide rules (commands, secrets, git, deployment) are in the root `CLAUDE.md`; the site is in `website/CLAUDE.md`. Setup and credentials: `README.md` here and `docs/worktree-setup.md`.

**Paths:** `src/…` and `tests/…` are relative to `payload/` (`hooks/`, `lib/` mean `src/hooks`, `src/lib`). Commands and `scripts/…` run from the repo root (`payload/src/scripts/` holds the `payload run` scripts such as `devAccess.ts`).

Payload 3 backend (Next.js admin + REST, Postgres; GraphQL disabled). Compose services `cms` (image `berliner-schnauze-cms`, media volume) and `postgres`. The Astro site reads it through the Local API (`getPayloadClient()` in `website/src/services/payload.ts`, `payload-app` workspace dependency; its types come from the `types` export condition).

## Commands

```bash
pnpm cms:dev                     # Payload admin + API (port CMS_PORT from .env.worktree, else 3001; secrets via with-env.sh)
scripts/with-env.sh pnpm cms:test    # Payload tests; they DELETE rows, so only against DATABASE_URL_TEST (a throwaway DB named *_test; each worktree has its own)
pnpm cms:migrate:create <name>   # After EVERY schema change; commit it. The cms container runs migrations on start (CI fails on drift)
scripts/migration-upgrade-test.sh [base-ref]   # DATABASE_URL=…_e2e: migrate with base-ref's code + seed, upgrade with this checkout, roll back, forward again (CI: migration-upgrade job)
scripts/migration-dryrun.sh <backup.dump|.sql>  # Before a risky deploy: restore a prod backup into a throwaway Postgres container, migrate, read every collection
scripts/with-env.sh env NODE_ENV=production pnpm cms:migrate   # Apply migrations to the worktree DB. Setup already did; once `cms:dev` pushed the schema, Payload marks the DB (batch -1) and migrate asks to accept data loss. To test migrations use migration-upgrade-test.sh, or reset the DB (orca-archive.sh + orca-setup.sh)
scripts/with-env.sh env NODE_ENV=production pnpm --filter payload-app dev:access   # (re)creates the dev admin and MCP key in a local DB
docker compose up --build cms postgres   # CMS image (payload/Dockerfile, context = repo root)
infisical run -- pnpm dlx tsx scripts/publish-drafts.ts --dry-run   # Publish all draft words via REST (PAYLOAD_URL, PAYLOAD_API_KEY)
```

## Schema and migrations

- Schema: dev and tests push it; production (`NODE_ENV=production`, pinned on `cms`) only runs the committed migrations, and only where `PAYLOAD_RUN_MIGRATIONS=true` (set on `cms` alone). Never point a push-filled DB at the prod container.
- **Migrations are expand/contract** (add nullable/default, drop or rename only in a later release; working `down`). Full rule and the schema-change steps: `.claude/rules/payload-migrations.md` (loads when you touch collections, globals or migrations).
- **Pending contract (do in the release AFTER the start-page v20 release)**: the `home` global still declares `facts` (`src/globals/Home.ts`, table `home_facts`). The website stopped reading it in v20 (`fetchHomeFacts` is gone), but the previous production `web` still does, and during a rolling release the old `web` runs against the new schema. Once v20 is live everywhere: remove the `facts` field from `Home.ts`, regenerate types, `pnpm cms:migrate:create drop_home_facts` with `DROP TABLE IF EXISTS "home_facts" CASCADE` and an idempotent `down`, and delete this bullet plus the "leftover" note in **Editable site texts**. Do not drop it earlier.
- **Partial unique index** `comments_one_featured_per_word_idx` (one published featured Jeschichte per word) exists ONLY in migration `20261122_165037_comments_bezirk_featured`: Payload cannot declare it, so dev/test databases built by schema push have just the `singleFeatured` hook, and a `migrate:create` or push may drop the index. Keep it in the migration; never rely on the hook alone in production.
- Schema push in dev asks interactively (rename vs. create, data-loss confirm). Without a TTY the dev server hangs at it; run `pnpm payload run <boot script>` under `script -qfec … /dev/null` and answer, or migrate.

## Access and drafts

- **Drafts**: the Local API ignores access control unless asked — every site query spreads `siteRead()`, or `siteDocs()` for drafts listings (`website/src/services/payload.ts`: `overrideAccess: false` + `req.context.siteRead`), and `draftsRead`/`contentRead` (`src/access.ts`) then return published docs only, also in populated relations. REST stays login-only (it cannot set `req.context`). `SHOW_TEST_DATA` includes drafts on purpose (`siteDocs()`).
- The comment collections (`comments`, `comment-votes`, `comment-reports`) are login-only; the site queries them outside `siteRead()` with its own `status` filter and `depth: 0` (`website/CLAUDE.md`, Word comments). Keep access and that filter in step.
- `bon-games` (BON game results) is login-only; the site writes it through the Local API. It holds a hash of the visitor cookie, the dealt cards with their solutions, the display name, the result and timestamps, no IPs; there is no delete-by-visitor tool, only the CMS (website/CLAUDE.md, BON game).
- `bon-players` (BON player codes) is login-only too: `codeHash` (sha256 of the code, unique) and `name`; games link to it via `bon-games.player` (deleting a player sets that to null).
- `bon-games.nameReports` counts „Namen melden“ reports; from `NAME_REPORT_LIMIT` (3, `lib/bonNames.ts`) on, or with `nameHidden`, the name shows as Anonym. The `afterChange` hook mails the editors once when the reports reach the limit; reset with Meldungen = 0.
- First admin: in production `PAYLOAD_ALLOW_FIRST_USER=true` gates `POST /api/users`, but Payload's `/api/users/first-register` bypasses it. Cutover: create the first admin before the proxy route goes public.

## Derived fields and exports

- **Derived word fields** (`derived` group) are computed on save by the `beforeChange` hook from `src/lib/wordDerived.ts`, which the site also imports as `payload-app/word-derived` — keep it free of payload/next/config imports. `derived.decomposition` (compound parts) comes from `src/lib/decompose.ts` instead, CMS only: its 28 MB dictionary never loads in the site. Changing the derivation leaves existing words stale until re-saved (there is no bulk tool; write a `payload run` script that updates every word with `req.context[PRESERVE_CONTENT_MODIFIED_AT] = true` to keep the sitemap lastmod).
- `payload-app` exports: `.` (types via `src/astro.d.ts`, a hand-kept types-only mirror of `src/index.ts` — update both), `./word-derived`, `./lexical-html`, `./routes` (collection → site path, shared by SEO, redirects and rich-text links), `./preview` (signed preview tokens), `./comments` (pure comment rules: limits, link check, auto-hide, pseudonyms, `idOf`; no payload/next/config imports, like `./word-derived`), `./word-feedback` (pure feedback rules: answer lists, `MIN_GROUP`; same import rule), `./bon-rules`, `./bon-player`, `./bon-names`, `./bon-ranking` (pure BON game rules, code format, name filter, ranking; same import rule, no payload/next/config imports; `bon-rules` and `bon-names` reach the client bundle, `bon-player` and `bon-ranking` import `node:crypto`, so the client takes only types from them), `./home-stats` (pure start page helpers: Morse ring, age groups, `MIN_WORD_VOTES`, `WordRef`; same import rule) and `./home-stats-load` (the start page aggregates `loadDailyStats`/`loadHourlyStats`/`loadHomeStats` in raw SQL: only aggregates leave it, every query needs `w._status = 'published' and w.deleted_at is null`; the site caches the two halves for 24 h and 1 h).
- **Start page seeds** (dev only, `src/seed/`): `pnpm --filter payload-app seed:home` fills the empty `home` fields, topic sayings, the newest post's teaser quote and placeholder IPA; `seed:home-stats` adds invented votes and BON games (fake `e2e-…` hashes) so map, age lists and BON card have data. Both refuse any database but a worktree's `bsw_<workspace>` (`assertDevDatabase`), only fill what is empty and report `written`/`alreadySet`/`unavailable`; `seedE2e` runs them too (guarded by `assertLocalDatabase`). The only test words are the invented ones of `seed:e2e`, listed in `docs/test-words.md` (a test keeps list and seed in step); there is no separate `testwort` seed.

## Trending words (`word-stats`, `src/lib/wordStats.ts`, export `payload-app/word-stats`)

- Collection `word-stats`: one row per word and Berlin day (`day` text `YYYY-MM-DD`, unique `(word, day)`), counters `views`/`audio`/`shares`/`clicks`. `bumpWordStat(payload, word, kind)` increments one atomically. Daily rows go away together with their word (`deleteComments` beforeDelete hook in `collections/Words.ts` removes `word-feedback`, `word-stats` and `reports` with `db.deleteMany` (no hooks) and `comments` through `payload.delete`; the FK is NOT NULL). No timestamps on the collection (privacy: created/updated would show one visitor's visit time).
- `collect()` aggregates per word with raw SQL (`drizzle.execute`: `GROUP BY word_id` on `word_stats`, `word_feedback` with a reaction, published `comments`): it bypasses Payload access and hooks, and its table/column names must follow any collection or migration rename.
- `trending(payload, { type, days, limit })` ranks published words only (`limit` applied inside). Interactions I = Audio + Teilen + Weiterklick + Reaktion (weight 1 each) + Kommentar (weight 3, published comments only); m = max(1, Σviews / words with views). `viewed` = views; `rising` = (jetzt − davor)/(davor + m), values ≤ 0 dropped; `engaged` = (I + m·rate)/(V + m).
- Site routes: `POST /api/word-pulse` (counts one report per IP, word, kind and Berlin day from an in-memory set, 404 for drafts, 429 after 2000 reports per IP and day) and `GET /api/trending?type=viewed|rising|engaged&days=7|30|365&limit=1..50` (defaults 30/10; one 5 min `ttl()` memo per type and days, stale while it refreshes (the top 50 is cached, `limit` cuts it), `Cache-Control: public, max-age=300`).

## MCP (`@payloadcms/plugin-mcp`, `src/mcp.ts`)

`/api/mcp` on the cms host, so Claude can find/create/update `words` and find/update `suggestions` (no delete). Auth is a per-user key from the admin (`payload-mcp-api-keys`, every capability off until toggled per key); the tools run as that user. The tools default to `draft: false` and take `_status` as an argument, so `hooks/mcpDraftOnly.ts` (keyed on the documented `req.payloadAPI === "MCP"`) refuses any MCP write that publishes or edits a published word without `draft: true`. Field access in `collections/Suggestions.ts` hides `userName`/`userMail` from every MCP request (read, write result, query; the tools run with `overrideAccess: false`), and `lib/mcpGuards.ts` writes one metadata-only audit line per finished tool call to the cms log (`onEvent`, prefix `[mcp]`; never arguments or results). Every tool takes an optional `select` (Payload Select API, e.g. `{ slug: true }`); without it each result is the full document, so the collection descriptions in `mcp.ts` tell the client to set it. The enabled flags are columns of the keys table: changing them needs a migration. `MCP_DISABLED=true` switches the endpoint off. The site bundle aliases the plugin to `website/src/lib/payloadMcpStub.ts` (production build): the plugin drags the TypeScript compiler into the bundle, which crashes on `__filename` and 500s every page. Client: the `payload` server in `.mcp.json` reads the key from the env var `PAYLOAD_MCP_KEY` (URL override: `PAYLOAD_MCP_URL`, default prod). Never commit the key: put it in the git-ignored `.claude/settings.local.json` under `"env": { "PAYLOAD_MCP_KEY": "…" }` (or export it in the shell), then restart Claude Code and approve the server. Local databases get a fixed dev key from `DEV_MCP_KEY` (`dev:access`); the client still points at production unless `PAYLOAD_MCP_URL` is set (root `CLAUDE.md`, Worktree setup).

## Other features

- **Cache stamp** (`globals/CacheStamp.ts`, `hooks/cacheStamp.ts`): `afterChange`/`afterDelete` hooks set the global `cache-stamp` (`changedAt`) in the transaction of the change, once per request; the web containers poll it and empty their page cache and memos (`website/CLAUDE.md`, Cache clearing). Only collections and globals in `STAMPED_COLLECTIONS`/`STAMPED_GLOBALS` stamp: **a new collection or global that changes a public page must be added there** (votes, reactions, stats and Bon games stay out: they write all the time and would keep the cache empty). `comments` stamp only when a public (published) comment appears, changes or leaves (hidden): held-for-review comments and the counter updates of votes and reports (`skipCommentHooks`) do not. `redirects` (a plugin collection) gets the same hooks through `overrides` in `redirects.ts`; `tests/cacheStamp.test.ts` fails when a collection or global of the config is neither stamped nor on its explicit not-public list. The stamp global has no hooks of its own.
- **Redirects** (`@payloadcms/plugin-redirects`, `src/redirects.ts`): `website/src/middleware/index.ts` answers a 404 with a matching redirect (`website/src/services/payload/redirects.ts`). Changing the slug of a public doc adds a 301 itself (`hooks/redirectOldSlug.ts`), also after withdraw → rename → republish (it falls back to the last published version's slug).
- **Draft preview**: the admin's preview button (words, posts) links to `/api/preview` with a token signed by `PAYLOAD_SECRET` (1 h); the site keeps it in an httpOnly cookie and renders the latest draft with `Cache-Control: private, no-store`. Admin and site are on different hosts, so the Payload login cookie is not used. The CMS builds the link from `SITE_URL`.
- **Jobs** (scheduled publishing of posts and the retention task) run only where `PAYLOAD_RUN_JOBS=true` (the `cms` container), never in the site's Local API process.
- **Retention job** (`src/jobs/retention.ts`, daily 03:30 UTC, only where `PAYLOAD_RUN_JOBS=true`): clears name and mail of accepted/rejected suggestions 90 days after their last update and of never-handled (`new`) ones after 365 days (via `db.updateMany`, so the lock hook does not block it). Deletes removed, hidden, pending (never approved) and self-deleted comments 183 days after their last update, with their votes and reports; a comment with replies is blanked like a self-delete instead (vote and report counters reset to 0, also for already self-deleted ones, so `updatedAt` moves on). It also removes the `visitor` hash of `word-feedback` rows 395 days (13 months) after their last update; the answers stay. `updatedAt` is the clock for all of this except reports (no separate timestamp). It also clears the e-mail of open reports 90 days after creation (`createdAt` is the clock); closing a report clears it at once. A failing comment is logged and skipped, the task then fails. The periods are promised in the privacy policy; change both together.
- **Admin stats** (`/admin/stats`, `components/StatsView.tsx`, nav link `StatsNavLink`): any logged-in user (a visitor without a login is sent to the login); range and choices live in the URL (`von`, `bis`, `reihen`, `ansicht` = linie|flaeche, `verteilung` = reaktion|nutzung, shown as the „Feedback-Diagramm“ row; parsed by `lib/statsParams.ts` / `lib/statsRange.ts`, `statsHref` is its inverse). Nothing asked: last 30 days. A `bis` in the future is cut to today, a range over 366 days loses its oldest days, garbage or reversed dates give the last 30 days; the page says so in a notice. Above 90 days the chart groups by ISO week. `lib/statsQueries.ts` `loadStats` sums the daily series per Berlin day in raw SQL (`word_stats`, `word_feedback` with a reaction, published `comments`, `suggestions`, finished `bon_games`) plus range totals (reaction split, top lists: views, „Beliebt“ = like share, „Typisch berlinerisch“ = „say“ share, both from `MIN_GROUP` votes). Totals count every word, also trashed and draft ones; only the top lists show published, untrashed words. Every tile and the comparison chart use the equally long range before (`previousRange`, loaded with `tops: false`); if only that one fails the page still shows. Raw SQL bypasses Payload access and hooks and its table/column names must follow any rename (`statsQueries.test.ts` checks the columns exist); `num()` throws on a non-number instead of showing „NaN“. Charts are Chart.js on a canvas (`components/stats/StatsCharts.tsx`, colors read from the admin CSS variables in `themeColors.ts`). `trending()` is separate and unchanged (reactions count there, the usage survey does not).
- **Trash and live link**: `words`, `posts`, `pages`, `themen` and `word-types` have `trash: true` (soft delete via `deletedAt`; Local API/REST reads skip trashed docs unless `trash: true`; a restore needs `trash: true` on the update too). Trashing keeps a word's comments, feedback and stats until the permanent delete (which runs `deleteComments`). Trashing or restoring does not move `contentModifiedAt` (sitemap lastmod). A trashed doc still holds its unique `slug`: the slug field and `adoptSuggestion` say so instead of a bare „must be unique“. Trashing a suggestion's published word unlocks the suggestion (like a delete). A scheduled publish of a trashed post fails (the job cannot find it) instead of publishing it; schedule again after the restore. The MCP cannot trash a live word (`mcpUpdateDraftOnly`, covered by `mcp.test.ts`). The sidebar `liveLink` field (`components/LiveLink.tsx`, `lib/liveLink.ts`) links a published doc to its public page, also when a newer draft is open; without `SITE_URL` it shows no link outside production. Admin sidebar groups (`admin.group`): Inhalt, Community, Spiel & Statistik, System. `defaultSort` is a collection option, not an `admin` one.
- **Editable site texts**: globals `home` (start page: intro, try-words, browse links, knowledge text, six sound rules, FAQ, about sentence; `facts` is a leftover of the old page, see **Pending contract** below; topic sayings and the magazine teaser quote/IPA live on `themen` and `posts`), `anki` (steps, features with `{liteWords}`/`{totalWords}`, FAQ), `company` (platforms, wallets, donation highlights, social links), `word-page` (word page: `storyPrompt`, the „Frage der Woche“ with `{Wort}`; empty = `STORY_PROMPT_DEFAULT`, filled by `storyPrompt()` in `lib/storyPrompt.ts`). Price (Polar) and layouts stay in code.
- **Word page data**: `words` has `stress`, `grammar` (`plural`, `diminutive`), `facts` (rich text `text`, `source` of exactly that entry, shown before the credit) and `related` (rows may link the contributing suggestion; `contributorName` is a public credit under the entry, hidden from MCP and not covered by the 90-day clean-up of suggestions: name it in the privacy policy; an MCP update replaces `facts`/`related` wholesale (the MCP row schema has no `id`), so `mcpKeepCredits` merges the stored `contributorName` back by row index (moving or deleting rows via MCP can shift a credit to its neighbour; MCP drafts are reviewed before publishing); a `related` row without a word keeps saving after its word was deleted (FK set null), only new rows need a word or label); `affiliate.books[].themen` ties a book to Themen; global `word-page` holds the Jeschichten question (`storyPrompt`, must contain `{Wort}`). The old origin text `infoText` and the word-wide `sources` are gone (migration `drop_v18_legacy_columns`): the migration `20261123_190000_info_text_to_facts` copied them into `facts` (kind herkunft) on the v18 deploy; its `up` is now empty, its `down` still removes the unedited copies.
- **Suggestions → words** (only `type: word` suggestions are matched and adopted; `example`, `fact` and `related` use `targetWord`, never `word` (that would lock them), and are copied into the word by hand, then set to accepted; `type`, `kind`, `relation` etc. are nullable in the database and enforced by `validate`; `hooks/adoptSuggestion.ts`, `hooks/suggestionLock.ts`, `lib/wordMatch.ts`): creating a suggestion or changing its Berliner Wort fills `similarWords` (same `matchKey` spelling, without its own word; a failing search is logged and skipped). Status `accepted` without a `word` creates a draft word and links it (an empty or taken slug is refused with 400); a hand-chosen `word` is only linked. A suggestion is locked while its linked word is published: derived from the word's `_status` (virtual field `lockedByWord`), so withdrawing or deleting the word unlocks it. The `update` access makes it read-only in the admin (REST/MCP get a 403); `refuseWhenLocked` is the backstop with a readable message for bulk and Local API updates. Deleting stays possible.
- **Suggestions/comments mail**: `afterChange` hooks mail the editors via Payload's nodemailer adapter (`SMTP_URL`, `SUGGEST_MAIL_TO`; without `SMTP_URL` to the console). Site side: `website/CLAUDE.md`.
