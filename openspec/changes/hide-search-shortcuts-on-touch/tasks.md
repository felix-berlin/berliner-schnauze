## 1. Resolve the detection mechanism

- [x] 1.1 Confirmed via context7 (VueUse docs): VueUse exposes `useMediaQuery(query)` — a generic reactive `ComputedRef<boolean>` wrapper around any CSS media query. Decision: use `useMediaQuery('(pointer: fine)')`, named `hasKeyboard` (affirmative signal reads clearer than a negated `!isCoarsePointer`). This is design.md's option 3, which turns out to directly wrap option 1's correct signal (pointer capability, not viewport width) in VueUse's reactive primitive — matches the project's "prefer VueUse over hand-rolled" convention with no downside.
- [x] 1.2 `useMediaQuery` is inherently reactive (a `ComputedRef`) — there is no extra cost to letting it stay live for the whole modal lifetime versus snapshotting it once, so no one-time-check logic is added. Bonus: if a Bluetooth keyboard connects mid-session, hints can correctly reappear without a remount.

## 2. Implement the conditional visibility

- [x] 2.1 Added `const hasKeyboard = useMediaQuery("(pointer: fine)")` in `SearchModal.vue` and wrapped only `ShortcutSelect`/`ShortcutNavigating`/`ShortcutClose` in a `<template v-if="hasKeyboard">` inside the existing `<footer v-if="!showWordListFilterFlyout">`. **Deviation from the literal task wording, on purpose:** the footer also contains `ModalCloseButton` — the real, functional close button. That must NOT be hidden on touch (touch users have no ESC key, so they need the tap-to-close button more, not less). Gating the whole footer would have broken modal-closing on touch; gating only the three hint components preserves both the close button and the existing flyout-based hiding.
- [x] 2.2 Confirmed via `git diff --name-only`: only `SearchModal.vue` changed. `ShortcutSelect.vue`, `ShortcutNavigating.vue`, `ShortcutClose.vue`, and `WordList.vue`'s `onKeyStroke` listeners are untouched.
- [x] 2.3 **Scope expansion found during live verification (task 3):** `src/components/word-search/WordSearchList.vue` renders `ShortcutSelect`/`ShortcutNavigating` unconditionally in its own `.c-filter-search__shortcuts` div, on the homepage inline word list — a second, previously unfound consumer. Confirmed via `grep -rln "ShortcutSelect\|ShortcutNavigating\|ShortcutClose" src/components/` that only `SearchModal.vue` and `WordSearchList.vue` use these components. Added the identical `hasKeyboard = useMediaQuery('(pointer: fine)')` gate around both components there.
