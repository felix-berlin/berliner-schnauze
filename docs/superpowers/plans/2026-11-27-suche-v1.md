# Suche v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `/suche` and the old `/wort` index with one server-rendered search page at `/wort` (Suche v1), a filterless header quick search, and an optional on-device Chrome-AI meaning search.

**Architecture:** One pure-TS search core (`website/src/lib/search/`) ranks, filters, counts facets and (de)serialises the URL. The Astro page builds an Orama DB from the in-memory index entries and SSRs the first virtua window; the Vue island then loads `/api/search/index.json` (as today) and searches locally. The index gains survey aggregates (raw SQL, 24 h `ttl`) and content flags; word of the day and trend ranks come in as SSR props.

**Tech Stack:** Astro (server output), Vue 3 `<script setup>`, Orama 3 + German stemmer, virtua `WindowVirtualizer`, Nanostores (only where a store already exists), Payload 3 Local API + `payload.db.drizzle`, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-27-suche-v1-design.md` (how and decisions) + `docs/design/suche-v1/SPEC.md` (binding copy, sizes, states). Markup/sizes: `docs/design/suche-v1/generator-suchev1.py`. Board screenshots: `suche-v1-handoff.zip` in the repo root (`assets/boards`, `assets/zustaende`), unpack into the scratchpad, never commit.

## Review Focus

1. **Typing fast while the index is still loading** (cold SW cache, 400 KB): old SSR rows must stay, no flash of „Keene Treffer“ — pinned in Task 8 (`keeps ssr rows until index ready`).
2. **Hand-edited or stale URLs** (`?wortart=foo&silben=9&alter=x`, duplicated params, old `/suche?q=` share links): unknown values dropped, page renders, redirect keeps the query — Task 3 (`drops unknown values`) and Task 7 (redirect E2E).
3. **Query of only punctuation/whitespace or one character** (`"  "`, `"-"`, `"ä"`): no crash, no highlight under 3 chars, „Keene Treffer“ only when really empty — Task 1 (`blank query`) and Task 3 (`highlight under 3 chars`).
4. **Words with < 10 votes under „Am meisten jesagt“ or a Gebrauch filter** and a Bezirk/age group under 10: never shown as 0 %, sorted last / excluded — Task 2.
5. **KI answer arrives after the user changed the query or filters** (or `LanguageModel` throws on `create`): stale result never shown, error state instead of a dead spinner — Task 11 (`discards stale answer`, `create rejects → error state`).
