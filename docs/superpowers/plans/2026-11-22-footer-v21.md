# Footer v21 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the site footer with Footer v21 „Wort zum Abschied“ (farewell with Kalle and a rotating word sign, three text columns, legal line, optional closing callout) on every page.

**Architecture:** `SiteFooter.astro` renders callout slot, dark band, columns and legal line on the server and is re-rendered on every navigation (no `transition:persist`). One Vue island `FooterFarewell.vue` owns the farewell (text, Kalle, `FooterWordSign.vue`); the server hands it ~30 shuffled words taken from the already cached `fetchAllWords()`. The app callout and the farewell share one nanostore that says whether the install callout shows.

**Tech Stack:** Astro 6 + Vue 3 islands, Nanostores, VueUse, SCSS (`mx.component`, `@scope`, DTCG tokens), Vitest, Playwright, axe.

**Spec:** `docs/superpowers/specs/2026-11-22-footer-v21-design.md` (design decisions) and the handoff `footer-v21-handoff.zip` (`SPEC.md`: copy, sizes, states, motion; boards `design/FooterV21*.dc.html`, screenshots `assets/v21/*.jpg`). Where they differ, the design doc wins. Read `.claude/rules/website-styles.md` and `.claude/rules/website-testing.md` before touching SCSS or tests.

## Global Constraints

- Copy is taken verbatim from `SPEC.md`. Never „wir/uns/unser“ (the site is run by one person: „ich/mir/mein“). No emojis, no Fraktur (`--font-display`), no brand logos, no claim that words are „mit Quellen belegt“.
- The word sign is the only card in the footer. No other surfaces or tiles.
- Colours only through **semantic** tokens (`--color-*`, `--band-*`, `--sign-*`); no hex, primitive or legacy alias in components (`.claude/rules/website-styles.md`). Logical properties, no `@media` (container queries inside components; breakpoints 808px = `50.5rem` and 1000px = `62.5rem` as container widths), no dark-mode code. Spatial animations inside `@include butler-mx.feature("motion")` (reduced motion = end state, no animation). Font sizes in `rem`, minimum 13px.
- Touch targets: `var(--size-tap-target)` (44px) for every footer link below the 808px container width (`data-variant="tap"` on textlink lists).
- Browser floor: Baseline widely available, Firefox ≥ 146. No `animation-timeline`, no element-scoped view transitions, no `text-decoration-skip-spaces`.
- Footer text 13px minimum; band `#14191e` in both themes via `color-scheme: only dark` on `<footer>` with `color` / `accent-color` set again on it.
- Tests contain no real words or text from the production database; use invented fixtures.
- pnpm only. Commit messages: `type(scope): description`, scope `footer`, ending with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Never `git add -f`; add explicit paths.

## Review Focus

1. **Pool smaller than 30, or just one word** (fresh database, E2E seed): „Noch eens“ must not break; with one word it is hidden, with an empty pool the sign is omitted and the farewell reads like the callout variant. (Task 2, 5)
2. **Page word not in the pool / slug unknown:** exclusion is a no-op, never throws; the page word never appears, also after „Noch eens“ cycled through the whole list. (Task 2)
3. **Word without article, without example, or with a 36-letter lemma** (`rinnsteinschwalbenbeobachtungsposten` in the E2E seed): no `undefined` text, no horizontal overflow at 390px, no height jump when swapping. (Task 5)
4. **`beforeinstallprompt` fires late or never:** server renders sign; if the app callout appears afterwards the sign disappears without losing keyboard focus in the page, and in Safari/Firefox (never installable) nothing changes. (Task 6)
5. **JS off / island not yet hydrated:** the SSR word and the whole footer stay readable and linked, „Noch eens“ is hidden until hydration. (Task 5, 8)

### Task 2: Word logic (pure)

**Files:**

- Create: `website/src/utils/footerWords.ts`, `website/src/tests/unit/utils/footerWords.test.ts`

**Interfaces:**

- Produces:
  - `type FooterWord = { slug: string; lemma: string; kind: string | null; meaning: string; example: string | null }` (`kind` = article and/or word type as one display string, e.g. „der“; `null` when neither exists)
  - `toFooterWord(word: SiteWord): FooterWord | null`: first non-empty `translations[].translation` as `meaning`, first non-empty example text as `example`; `null` when the word has no meaning (it cannot be shown)
  - `pickFooterWords(words: SiteWord[], excludeSlug?: string, count = 30, random = Math.random): FooterWord[]`: shuffles (Fisher–Yates with `random`), drops `excludeSlug` and words `toFooterWord` rejects, returns at most `count`
  - `createWordCycle(words: FooterWord[], random = Math.random): { current: FooterWord | null; next(): FooterWord | null }`: starts with `words[0]` (the SSR word), `next()` walks a shuffled order without repeating until all are used, then reshuffles so the first word after a reshuffle differs from the last shown; one word → `next()` keeps returning it
  - The two-line cut of meaning and example is CSS (`line-clamp: 2`), not JS.
- Consumes: `SiteWord` from `@services/payload/words.ts`.

- [ ] **Step 1: Write failing tests** with invented `SiteWord` fixtures (small helper `word(slug, over?)`): `pickFooterWords` never returns the excluded slug; returns ≤ `count`; works with fewer words than `count`, with `[]` and with an unknown `excludeSlug`; skips words without meaning; is deterministic with a seeded `random`. `createWordCycle`: all words appear once before any repeats, the first word after a reshuffle differs from the last shown, a single-word list and an empty list do not throw, `current` starts as the first word.
- [ ] **Step 2:** `pnpm vitest run src/tests/unit/utils/footerWords.test.ts` → FAIL (module missing).
- [ ] **Step 3:** Implement the module; read the example field name from `WordExamplesArray` in `payload/src/payload-types.ts` and the article/word-type display from `SiteWord` (`article`, `wordTypes[].name`).
