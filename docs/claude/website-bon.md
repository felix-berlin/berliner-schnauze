# BON game (website)

Moved verbatim from `website/CLAUDE.md`. Read before changing `pages/api/bon/`, `useBon`, `services/bon*` or the leaderboard.

- **BON game** (`src/components/games/`; spec `docs/design/bon/SPEC.md`, mocks beside it: copy is binding, deviations are marked "Abweichung (Umsetzung)"): server-driven and plays without cookies. `useBon` (phases intro, play, feedback, loading, error, over) deals cards from `POST /api/bon/{start,next,answer,finish}` (`src/pages/api/bon/`, `services/bonGame.ts`, `bonPool.ts`, `utils/bonDeck.ts`, server rules in `payload/src/lib/bonRules.ts`, whose `LIVES` and `computeMultiplier` `useBon.ts` imports from `payload-app/bon-rules`); the client never holds a solution, every card is checked by `answer`. Client state is only `$bonStats` (record, streak, name, `hasSeenIntro`); there is no `$savedBon`, a reload ends the run. `start` always deals and sets the httpOnly visitor cookie; `next` and `answer` find the game by token alone (404 for unknown or finished tokens); only `finish` needs the cookie (400 without, then the result shows no place); it answers the result plus `rank`, `totalPlayers` and `around` (the own row with two neighbours each side) from the week's leaderboard (best game per identity, same as `/rangliste`); the result asks `GET /api/bon/leaderboard` again only after a rename. `answer` reveals one card (`isReal`, translation, slug, category, lives, gameOver; 409 for any position but the next) and stores the guess in `bon-games.cards`; `finish` replays those answers (body `{ token, playerName? }`), checks the server-clock time per card, is serialized per token by an in-process lock (a second web container needs a DB-level conditional update) and ranks only games that end at the third mistake or answered all `MAX_BATCHES` (20 batches = 400 cards, `services/bonGame.ts`). `bon-games` keeps only a hash of the cookie; the public card id is the position (`"0"`, `"1"`, …), the internal `r<wordId>`/`f<index>` ids never leave the server. The client keeps at most one `next` in flight (max 20 batches = 400 cards). `start` deletes unfinished games older than 24 h. Rate limits: `utils/rateLimit.ts` (in memory; off on the e2e server, `E2E_SERVER`). Known limits: a bot that waits the minimum time, or looks up every word, is not caught; new cookies start new pseudonyms. Also: leaderboard `/games/berliner-oder-nicht/rangliste` (`BonLeaderboard.vue`, `GET /api/bon/leaderboard`), names filtered on save (`finish` stores Anonym when an earlier game of the identity hid the same name; `payload-app/bon-names`, far-right names get the EXIT-Deutschland notice) plus „Namen melden“ (`report-name`: one report per client network, game and name within 30 days; a name shows as Anonym from `NAME_REPORT_LIMIT` = 3 reports), nameless players show as `Anonym #TAG`, share links via URL query params (`src/utils/bonShare.ts`). Motion (spec §13): `vt()` in `utils/viewTransition.ts` wraps phase changes (view transition types, matched with `:active-view-transition-type()`; names `bon-card`, `bon-score`, `bon-me`, `lb-list`); `BerlinerOderNicht.vue` shows a lagging `view` so intro and HUD stay up for the morph; input locks are `CARD_LOCK_MS`/`FEEDBACK_LOCK_MS` in `useBon.ts` (= animation length); reduced motion = no animation. A named element that disappears ends a running view transition, so the leaderboard keeps its skeleton row until `navigationSettled()` says the navigation morph is over.

- **BON player code** (`pages/api/bon/{player,redeem}.ts`, `services/bonPlayer.ts`, `bonPlayerApi.ts`, `utils/bonFragment.ts`, `BonPlayerCode.vue`): one code per player, cookie `bon_player` holds it, DB only `sha256("bon-code:"+code)` in `bon-players`; link `/games/berliner-oder-nicht#code=…` (head script stores it in sessionStorage, strips the fragment before Matomo); privacy text lives in the CMS. Renaming (`BonName.vue`, `PATCH`/`GET /api/bon/player`) rewrites all games of the identity (visitor games already claimed by a code player excluded), resets name reports only on a real change, allows 5 per identity per fixed 24 h (in memory) and invalidates the ranking cache; for a code player `finish` uses a non-empty `bon-players.name` over the name the device sends, and writes the game's name there only when the lookup succeeded, none is stored and it is not „Anonym“ (a rename to „Anonym“ stores that literally, so it sticks across devices). Name inputs drop format characters (bidi overrides, zero-width; ZWJ stays) before the filter.
